# SOC Threat Hunting Project Report

## 1. Overview

This project implements a PowerShell-based SOC investigation workflow that analyzes authentication, web access, and PowerShell execution logs to identify suspicious activity and produce an incident report.

Primary objectives:

- Detect brute-force or repeated failed authentication attempts.
- Identify suspicious web request paths in HTTP access logs.
- Match indicators of compromise (IOCs) against observed activity.
- Flag suspicious PowerShell execution behavior.
- Produce a human-readable investigation report with risk scoring.

## 2. Repository Structure

- ProjectDataset/auth.log = Authentication events used for failed login and IOC checks.
- ProjectDataset/access.log = Web access events used for suspicious path checks and IOC checks.
- ProjectDataset/powershell_log.txt = PowerShell command activity for suspicious pattern detection.
- ProjectDataset/ioc.txt = IOC list (currently includes both IPs and web paths).
- scripts/run.ps1 = Main and most complete investigation script.
- scripts/ThreatHunter.ps1 = Earlier/alternate script version with logic and variable issues.
- scripts/investigation_report.txt = Output report generated by scripts.

## 3. Current Investigation Logic

The main script (scripts/run.ps1) performs:

1. Failed login detection by searching auth.log for "Failed password".
2. Suspicious web path detection in access.log for:
	- /admin
	- wp-login
	- .php
	- /etc/passwd
3. IOC matching against auth.log (and later auth.log + access.log for summary).
4. Suspicious PowerShell pattern detection in powershell_log.txt for:
	- EncodedCommand
	- Bypass
	- Invoke-WebRequest

5. Risk calculation:
	- High Risk: 3 or more alerts
	- Medium Risk: 1-2 alerts
	- Low Risk: NO alerts

## 4. Verified Execution Results

A fresh execution of scripts/run.ps1 produced:

- Total Alerts: 5
- Final Risk Level: High Risk
- Major detections:
  - 713 failed SSH password attempts in auth.log
  - Suspicious web paths detected (/admin, `wp-login, .php)
  - Suspicious PowerShell usage including -ExecutionPolicy Bypass, -EncodedCommand, and Invoke-WebRequest.


## Key Features & Enhancements

### Log Detection Engine
- Scans `auth.log`, `access.log`, and PowerShell execution logs for suspicious activities.
- Matches extracted patterns against known Indicators of Compromise (`ioc.txt`).

### Threat Intelligence & Live Alerting (New)
- Automated Threat Intel:** Integrates AbuseIPDB API v2 to retrieve real-time threat reputation scores for suspect IPs.
- Discord Webhook Alerts:** Formats and dispatches instant alert payloads directly to a designated Discord analyst channel.
- Input Sanitization:** Uses regex to filter out web paths and comments, ensuring accurate API queries and payload delivery.



## 5. Security Findings

- Authentication logs indicate sustained brute-force behavior and credential-guessing attempts against privileged and invalid users.
- Access logs contain suspicious path requests consistent with reconnaissance and web exploitation probing.
- PowerShell logs show high-risk execution patterns associated with post-exploitation behavior:
  - Encoded command execution
  - Policy bypass usage
  - Web download/upload behavior

Overall, the observed activity pattern supports a High Risk classification.

## 6. Quality Review of Scripts

### Strengths

- Clear and understandable SOC workflow logic in run.ps1.
- Good terminal feedback and file-based reporting.
- Multiple telemetry sources are correlated in one run.

### Gaps and Issues

- ioc.txt mixes IPs and web paths in one file. The IOC loop in run.ps1 treats all non-empty lines as IP-like indicators, causing path entries to appear under "Malicious IPs Found".
- run.ps1 searches Invoke-WebRequest without context, so benign web requests are flagged together with malicious ones.
- ThreatHunter.ps1 contains an undefined variable usage (`$accessLog`) and has two disconnected report flows, making it unreliable as a primary script.
- Reports are very large because every failed password log line is written. This reduces readability for analysts.

## 7. Recommended Improvements

1. Split IOC sources:
	- ioc_ips.txt = for IPs only
	- ioc_paths.txt = for web paths only
2. Parse and skip comment/header lines in IOC files (for example lines starting with `#`).
3. Improve PowerShell logic by distinguishing benign and suspicious Invoke-WebRequest patterns.
4. Add deduplication and capped output (for example top N entries per detection) to keep reports concise.
5. Keep run.ps1 as the canonical script and refactor or archive ThreatHunter.ps1.
6. Add an "evidence summary" section (counts by source IP, most targeted usernames, top suspicious URLs).
